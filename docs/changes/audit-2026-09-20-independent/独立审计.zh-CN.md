# RoboTenon 当前工作区独立审计

[English](%E7%8B%AC%E7%AB%8B%E5%AE%A1%E8%AE%A1.md) · [**简体中文**](%E7%8B%AC%E7%AB%8B%E5%AE%A1%E8%AE%A1.zh-CN.md)

结论：系统已有完整的插件装配、图调度、进程 Worker 和观测链路，但执行终止、任务身份、模型结果校验和配置一致性仍有可复现缺口。下一阶段应先让“任务确实执行完、停止确实完成、结果确实可信”成立，再扩大并行实验和插件接入范围。接真机前还必须关闭本文的动作取消、同步驱动和幂等冲突问题。

本次基于 `3e23ae2067e913ff80720855ee77b0ca77d01150` 加未提交改动的工作区快照，覆盖新增的基础设施插件注册表、Environment 参数传递、运行时和测试。先检查实现并设计故障场景，再核对旧审计。审计期间其他工作更新了文档；交付核对时，快照中的业务代码、配置、测试、构建文件均未发生变化。具体时间和 396 个文件的摘要见 [source-manifest.json](source-manifest.json)。

验证环境为 macOS arm64、Python 3.11.10、Pydantic 2.13.5。既有 Python 测试 **440 通过、1 跳过**，JavaScript 测试 **20 通过**。跳过项是 Linux 原生渲染崩溃 / preload 集成。本次另编写的 **11 项故障探针全部复现了对应缺陷**；这里“探针通过”表示问题存在，不表示行为正确。全部验证使用隔离代码副本、临时数据、假驱动或本次创建的本地子进程，没有连接模型服务、GPU 服务器或机器人，没有修改业务代码。

**R01 — Portal 的停止确认没有覆盖独立 Worker 进程组**

证据：[experiments.py:224](../../../robotenon/web/experiments.py#L224)、[experiments.py:263](../../../robotenon/web/experiments.py#L263)、[parallel.py:66](../../../robotenon/runtime/parallel.py#L66)、[parallel.py:307](../../../robotenon/runtime/parallel.py#L307)。

Portal 默认只给 Coordinator 3 秒退出时间，而 Worker 自己通过 `setsid()` 建立独立进程组，内部清理预算默认为 10 秒。Coordinator 已有 SIGTERM → asyncio 取消处理，但 Worker 阻塞时，Portal 会先把 Coordinator 强杀，来不及执行后续 Worker 进程组清理。随后仅检查 Coordinator 是否退出，就返回已释放。

探针使用真实进程后端和阻塞的假 TaskAdapter，获得 `released=true / coordinator_exit=-9 / worker_state=Ss`。已经验证的是 Worker 残留；真实模型进程和 GPU 资源是否残留，本次未连接硬件验证。依据同组模型生命周期，存在资源持续占用和下一实验与旧进程重叠的风险。

改进：由一个明确的所有者记录并回收整个实验的 Coordinator、Worker 和模型进程组；外层宽限预算要覆盖内层清理预算，但不能只靠延长等待修复。强杀 Coordinator 后仍须能独立回收 Worker，并核实整个执行域退出后才设置 `released`、释放资源及派发下一实验。验收覆盖 Worker 阻塞、模型子进程残留、Coordinator 强杀三种情况。

**R02 — 直接取消动作不会发送低层停止**

证据：[body.py:381](../../../robotenon/services/body.py#L381)、[body.py:412](../../../robotenon/services/body.py#L412)、[body.py:489](../../../robotenon/services/body.py#L489)；图停止会取消分支：[scheduler.py:354](../../../robotenon/workflow/scheduler.py#L354)。

`execute()` 的 CancelledError 分支执行可选 safe action，却未调用 `_invoke_stop()`。默认没有 safe action 时，它直接返回 interrupted，随后清空 `_active_task`。再调用 `close()` 也不会进入中断路径。探针确认：已提供 stop_executor，直接取消 execute 并 close 后仍是 `stop_calls=0`，线程中的假驱动继续执行。

改进：统一外部取消、graph.stop、分支失败和服务关闭的动作终止流程，发送有界低层停止并保留停止确认；外部取消语义应继续向上层传播。线程仍在途时禁止新动作，不能用协程结束代替驱动完成。验收必须检查停止回调和实际驱动状态，而不只检查返回值 `interrupted`。

**R03 — 模型布尔值必须严格校验**

证据：[verify.py:96](../../../robotenon/modules/verify.py#L96)、[verify.py:123](../../../robotenon/modules/verify.py#L123)。

`bool(output.get("subtask_success", False))` 把字符串 `"false"`、非空列表和对象都视为真。当前接口复现中，输入 `"false"` 导致 `subtask_success=True`、`completed=["pick"]`、`remaining=[]`。它首先污染 STM 和重规划依据；不能据此断言所有环境都会被直接判为最终成功。

改进：对 Tool 输出使用明确的 schema，成功字段仅接受 JSON boolean；格式错误返回可诊断的模型输出错误或 UNKNOWN，并保留原始返回用于审查。验收覆盖 false/true、字符串、null、缺字段和错误类型，同时检查 STM 未被错误修改。旧审计脚本因新的 `ctx.inputs` 契约已不能直接复现，本次已按当前接口重写验证。

**R04 — case 的调度身份与持久化身份不一致**

证据：[base.py:51](../../../robotenon/task_adapters/base.py#L51)、[evaluator.py:300](../../../robotenon/task_adapters/evaluator.py#L300)、[evaluator.py:576](../../../robotenon/task_adapters/evaluator.py#L576)。

`TaskCase.key` 只有 adapter/task/episode，不包含 index 或 seed；产物路径包含 seed，Trace 身份包含 index。两个同名 task、episode=0、index 不同、seed 不同的 case 能通过路径去重，但同时派发时后者覆盖 `running[case.key]`。快速任务完成后，调度器丢失慢任务的引用，提前返回。探针得到 `completed=1 / total=2 / status=completed`，另一个任务仍在等待。

改进：统一调度、控制命令、Trace 和结果记录的唯一 case 身份，例如 adapter_id＋唯一 index，并在枚举结束、产生副作用前校验身份唯一性。重复键必须明确拒绝。验收同任务多种子并行、按 index 单独停止/重跑，以及完成数量必须等于终态 case 数量。

**R05 — RealRobotBody 的 async 外壳隐藏同步阻塞**

证据：[real_robot_body.py:108](../../../robotenon/bodies/real_robot_body.py#L108)、[real_robot_body.py:132](../../../robotenon/bodies/real_robot_body.py#L132)、[body.py:593](../../../robotenon/services/body.py#L593)。

父类看到的是 async `_execute_action`，因此跳过同步执行隔离；包装内部却先直接调用 `driver.execute()`，之后才检查返回值是否 awaitable。同步 execute/hold/health/start 都可能阻塞事件循环。假 SDK 睡眠 120 ms、动作 timeout=25 ms，结果仍 succeeded，20 ms 定时任务也只能等驱动结束后运行。

改进：在真正调用 SDK 的边界隔离同步方法，保留在途驱动保护；停止通道不能排在阻塞动作之后。验证 execute、hold/stop、health、start 的响应预算和失败升级。软件修改不等于硬实时或硬件急停验收，真机仍需独立控制器保护和停止证据。

**R06 — 本地免登录设计与默认 Compose 暴露范围冲突**

证据：[access.py:9](../../../robotenon/web/access.py#L9)、[server.py:38](../../../robotenon/web/server.py#L38)、[docker-compose.yml:52](../../../docker-compose.yml#L52)、[docker-compose.yml:99](../../../docker-compose.yml#L99)。

Portal 明确采用 localhost / SSH 隧道保护，忽略传入 token。Host 和 Origin 检查仍存在，但它们不能认证直接 HTTP 客户端；探针确认，不提供 Authorization、发送受信 Host 的控制请求会通过。Compose 同时将 8765/3000/9090/9100 按未指定宿主 IP 的方式发布，Grafana 还启用匿名 Editor 与默认 admin 密码。

改进：保留本地免登录也可以，但默认 Compose 宿主端口应显式绑定 127.0.0.1，或不发布内部服务端口；对外部署另行提供认证入口和凭据配置。无认证非回环运行应需要明确的受控部署配置。验收既检查应用 Host/Origin，又检查实际监听与宿主发布范围。

本条确认的是代码边界和仓库默认部署配置；未启动 Docker、扫描网络或验证当前机器公网可达，因此不将它描述为已经发生的远程入侵。默认容器是否装载可运行配置会限制具体控制能力，不会补上访问认证。

**R07 — 每个任务重新读配置，使一个实验混用不同版本**

证据：[worker.py:92](../../../robotenon/runtime/worker.py#L92)、[runner.py:526](../../../robotenon/runtime/runner.py#L526)、[factory.py:882](../../../robotenon/runtime/factory.py#L882)。

Worker 保存 `loaded` 并复用 Tool；episode 使用该快照中的参数和 Graph，却又通过配置路径重新 `initialize_application()`。探针在两个任务之间将 Echo Module 参数从 before 改为 after，Worker 保存的 Module 清单仍为 before，第二次输出已经是 after。同一长期实验可混用旧 Tool/Graph 与新 Module/Body/Safety 配置。

改进：提交实验时保存合并后的不可变配置及其关联清单，Worker、任务装配和子进程均使用同一快照。显式热更新应形成新配置版本和执行身份。验收在任务之间修改所有源配置文件，既有实验仍使用原快照，新实验使用新配置。

**R08 — 幂等键未绑定动作内容**

证据：[body.py:177](../../../robotenon/services/body.py#L177)、[actions.py:49](../../../robotenon/storage/actions.py#L49)。

成功去重只依赖 session/key，未保存或核验请求摘要。相同 key 依次发送 target=1 和 target=2，第二次返回 succeeded，实际只执行了 target=1。调用方的键冲突被静默转为错误成功确认。

改进：将幂等键绑定规范化的动作类型、有效载荷和目标执行资源摘要；相同键、不同业务内容明确拒绝，相同内容重试才复用结果。不要直接把每次变化的时间戳或 attempt 身份放入摘要。验收同时覆盖内存缓存、账本重启和冲突请求。物理动作完成但 ack 尚未持久化的窗口仍需 UNKNOWN / 对账协议解决，本次没有宣称能够由摘要消除。

**R09 — 观测接入关闭没有上界**

证据：[ingest_server.py:66](../../../robotenon/infra/ingest_server.py#L66)。监听关闭后，对仍在 `reader.readline()` 的所有 handler 无界 gather。空闲客户端不发送也不关闭即可使 close 一直等待；探针观察到等待 150 ms 后仍未返回，主动关闭客户端才结束。

改进：跟踪 writer，关闭入口后主动关闭连接，按预算 drain 并取消剩余 handler，明确后台存储线程的回收边界。验收空闲连接、半条消息、写入失败三条退出路径，观测服务不得无限阻塞实验清理。

**R10 — 清理失败后 Worker 没有失效状态**

证据：[worker.py:67](../../../robotenon/runtime/worker.py#L67)。`run_task()` 的 finally 只重置 `_busy`，Tool 的 `end_session()` 失败不会淘汰常驻资源。连续两个任务的事件序列是 `start → cleanup_failed → cleanup_failed → close`；没有第二次 start，说明第二个任务仍使用原实例。

改进：将任务清理失败与普通任务失败区分，Worker 进入不可复用状态；关闭并重建 Tool 或终止该 Worker。统一进程内与进程后端的失效语义。验收包含清理抛异常、清理超时以及原始业务错误与清理错误同时存在。

**R11 — 新运行没有原子预约输出身份**

证据：[experiment.py:179](../../../robotenon/runtime/experiment.py#L179)、[evaluator.py:254](../../../robotenon/task_adapters/evaluator.py#L254)、[evaluator.py:510](../../../robotenon/task_adapters/evaluator.py#L510)。默认 run_id 只有秒级精度；目录存在也会继续运行。探针连续提交相同 ID 的新运行，旧 episode 的 attempt 身份被替换，没有冲突错误。

改进：默认 ID 加随机唯一部分，并在建立共享观测或写文件之前原子预约运行目录；已存在的新 run 拒绝，重跑和恢复使用显式接口及运行锁。Portal 的原地重跑能力可以保留，但不能与普通新运行共用无校验的覆盖路径。

**建议的实施顺序和验收重点**

1. 先修 R01、R02、R03：统一整个实验的停止所有权，明确动作停止确认，严格约束模型成功字段。这些直接影响运行资源、动作状态和实验结果的可信度。
2. 收敛运行身份与配置：R04、R07、R11 一起处理，让一个 case、一份配置和一组产物在调度、Trace、控制接口之间保持同一身份。
3. 补齐资源异常生命周期：R09、R10。关闭必须有预算，失败后的资源不得自动恢复为可复用。
4. 真机接入前完成 R05、R08 及 R02 的控制器级验收；共享网络部署前完成 R06。
5. 把 11 项探针改为期望正确行为的正式回归测试，并为 Linux 进程组清理、Python/Pydantic 支持范围建立持续验证。仓库当前没有提交 CI 配置；本次 macOS 测试不能代替 GPU 和 Linux 原生故障验证。

结构上优先拆清执行所有权：`web/experiments.py` 目前同时承担队列、进程控制、状态修复、媒体解析和数据投影，约 3395 行；运行状态应由执行控制层维护，Web 消费状态并发送命令。这样 R01 的停止确认和 R04 的完成判定可以有一个共同的权威来源。随后再将配置快照、严格模型输出校验和生命周期接口做成所有插件共享的契约。

已有六类业务插件及基础设施 provider 注册表、图调度、CAS checkpoint 和动作账本具有可继续演进的基础；本次不建议为解决这些缺陷重写整套系统。需要补的是端到端契约和异常场景验证。Coordinator 自动接管、物理动作对账、观测新鲜度准入、固定多种子评测仍应单独设验收目标；不应从现有单元测试通过推导这些能力已经完成。
