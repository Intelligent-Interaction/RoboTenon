## 修复内容

| 编号 | 修复 |
| --- | --- |
| A01 | 为框架配置和 Graph 配置增加严格模型，未知字段在加载时拒绝；插件自有值继续放在 `params` 或 `metadata`。主配置先投影到对应清单，避免模型、运行参数等其他主配置字段影响清单解析；环境、监视器和观测持久化中的兼容别名先规范化。 |
| A02 | 批量请求保存 `graph_id`，图选择、每个 episode、Worker profile 和冻结配置快照使用同一 Graph。 |
| A03 | CLI 预检按批量或单任务入口加载有效请求；校验批量适配器覆盖目标和启用项、模型端口范围、输出目录路径中非目录的已存在组件，以及单任务输出文件目标。 |
| A04 | 大于读取预算的旧 `summary.json` 现在写入单个任务的 `summary_error` 诊断，并继续到索引恢复调度，不再中断任务或列表查询。 |
| A05 | Graph 调度器按已发布结果对象复用不可变冻结值；没有 ready 节点时直接返回，不构造结果快照。不同激活仍持有独立的外层快照和执行屏障。 |
| A06 | 观测历史使用 SQLite 窗口函数抽取间隔样本，只解码返回项；`length × interval` 上限为 100,000，HTTP 超限返回 400 和明确原因。 |
| A07 | Metrics WAL reload 使用打开文件描述符的设备号和 inode 识别替换；文件身份变化或截断都会从头重建读取状态。 |
| A08 | `/api/runs` 改用持久 SQLite manifest 索引，首次读取回填旧记录，查询在数据库内按 `limit` 取最近结果。Recorder 写入和更新 manifest 后同步注册索引；索引不可用时保留旧扫描作为可用性回退。 |

## 后续审计修复

复核上述实现后又补齐了以下边界：

- 原始主配置和子清单在规范化、合并、投影前检查未知字段，避免顶层拼写错误被投影过程丢弃。扩展参数需要放在 `parameters`、`params` 或 `metadata`。
- 批量预检与运行共用 Task Adapter 插件加载、覆盖合并、构造和无副作用参数校验；无效试验数等错误会在预检阶段返回失败。
- Run 索引查询会移除已删除 manifest；索引注册失败会写入脏标记，在下一次成功查询时完整核对。Queue SQLite 也进入目录索引，`/api/runs` 不再递归发现并读取所有队列库。
- 观测历史同时限制返回 1,000 项和扫描窗口 100,000 条，并增加 0.5 秒查询时间与 3 MiB 解码预算。

配置严格校验只应用于框架定义的配置模型。自定义模块、工具、环境、监视器和适配器的参数仍可放在明确的扩展字段中；Graph 节点的自定义元数据仍放在 `metadata`。拼错框架字段现在会使加载失败，用户应按校验错误修正配置。

旧 run manifest 的首次回填会扫描一次历史目录；后续 Portal 查询使用 SQLite limit。之后由 RoboTenon `EpisodeRecorder` 创建或更新的 manifest 会同步进入索引。由外部程序直接复制进目录的新增 manifest 不会触发该钩子；需要重建该目录下的 `.robotenon-run-index.sqlite3` 才会再次回填。索引目录不可写或 SQLite 不可用时，Portal 会回退到旧扫描路径。

## 验证边界

后续审计增加了配置边界、批量预检、Run 索引恢复、队列目录和观测查询预算的回归测试。全量测试为 531 通过、1 跳过；没有启动模型、GPU、仿真或真实实验，Graph 调度优化的真实负载性能收益仍需在目标部署上压测。
