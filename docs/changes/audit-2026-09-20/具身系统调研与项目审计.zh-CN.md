**具身系统方案调研与 RoboTenon 项目审计｜2026-09-20**

维护说明（2026-09-20）：本文保留审计当时的证据和结论。后续插件/基础设施解耦修复请对照[当前接入检查报告](../plugin-extension-audit.zh-CN.md)与[基础设施契约](../../infrastructure-plugins.zh-CN.md)，不要将历史限制作为当前接口说明。

审计对象：当前工作区的 `robotenon/`、配置、测试，以及 `embodied-design/audit-v2/具身系统设计方案-v2.1-融合版.md`。这是对工作区快照的评估，文件摘要见同目录 `source-manifest.json`。未修改业务实现，未连接机器人、GPU 服务器或模型端点。

**结论：建议保留现有分层架构，将项目定位为可审计的具身执行与实验平台。当前强项是模块边界、模型资源复用、故障隔离和可观测性；短板是物理执行契约、验证可信度、实时控制和真实任务效果证据。继续增加框架功能的收益，已经低于补齐这些边界的收益。**

当前不宜把“有真机适配接口”等同于“真机系统已验收”，也没有证据证明现有 HLP＋VLA＋Verifier 比同条件下直接运行 VLA 更有效。设计 v2.1 对 fencing、物理对账、独立保护的要求较完整，但其中不少仍未进入默认实现。

证据分三种：**复现确认**为本次本地执行得到；**静态确认**为当前代码直接支持；**历史记录**为仓库已有实验文档，本次未重新读取服务器原始数据。外部方案只采用官方页面、作者论文或官方仓库；代表路线不构成穷尽清单，也不将厂商演示视为本项目可达到的性能。

**二、现有系统值得保留的优势**

| 优势 | 当前证据 | 实际价值及适用范围 |
|---|---|---|
| 动作与观测职责分离 | `services/body.py`、`services/environment.py`、`workflow/operations.py` | 默认图动作走 Body，Monitor 观察并发布结论。提供集中检查与审计位置；这是框架约定，尚非隔离恶意插件的权限沙箱。 |
| 常驻 Tool 与任务状态分离 | `runtime/worker.py`、`runtime/runner.py` | 模型、连接可以复用，Environment/Module/Context 按任务创建，适合昂贵 VLA 的批量评测。清理失败后的复用例外见 A04。 |
| 任务并行与图并行区分 | `runtime/parallel.py`、`workflow/scheduler.py` | 多进程隔离原生仿真崩溃；图中 wave、依赖与路由有专门实现。图并行仍不代表物理资源可以并行。 |
| 恢复语义比较诚实 | `storage/context.py`、`storage/actions.py`、`docs/architecture.md` | checkpoint/CAS、配置指纹、成功 ack 去重已具基础；文档明确不承诺物理 exactly-once。 |
| 可观测性有统一身份 | `runtime/observability.py`、`infra/observation_*` | attempt/worker/run 及观测 URI 有助于回放和故障定位，降低把图片数组塞入上下文的成本。异步遥测不是零丢失证据库。 |
| 有持续回归与事故记录 | 本次 265 项正式测试通过；已有 worker 崩溃与缓存竞态记录 | 比只展示单次成功 demo 更利于工程迭代，但正式测试仍遗漏本次复现的边界。 |

这些优势是对“把模型直接接入 env.step 的单脚本原型”的工程优势，不代表胜过成熟机器人控制平台或领先基础模型团队。

**三、优先修复的具体问题**

优先级按本项目影响定义：P1 为应尽快修复、或接真机前必须关闭；P2 为重要可靠性和评测改进。本审计优先级与运行时安全等级 P0–P4 无关。

| 编号 | 优先级 | 发现、触发条件与影响 | 证据与建议 |
|---|---|---|---|
| A01 | P1，真机阻断项 | `RealRobotBody` 的 async 包装内部直接调用同步 `execute()` / `hold()`。同步 SDK 阻塞事件循环时，watchdog 和 `wait_for` 超时也无法及时运行。 | **复现确认**：25 ms 超时的动作在假驱动中阻塞 120 ms，20 ms 定时任务到驱动结束才运行，动作仍回报 succeeded。`bodies/real_robot_body.py:108–149`；父类 `services/body.py:570` 看到的是 async 包装，未进入同步线程分支。修复要覆盖 execute/stop/start/health，保留在途线程 busy 保护；最终采用独立本地 watchdog，并验证停止确认。 |
| A02 | P1 | Verifier 用 `bool(output.get(...))` 解析成功字段；模型返回合法 JSON 的字符串 `"false"` 会被当作真，子目标被移入 completed。 | **复现确认**：`modules/verify.py:98–127`。用严格 schema/StrictBool，未知或格式错返回 UNKNOWN/错误；不得把模型自由文字直接写成物理事实。现有环境成功门禁能限制最终误停，不能消除错误 STM 和重规划。 |
| A03 | P1，动作与恢复契约 | 同一 session＋幂等键携带不同 payload，Body 返回旧成功 ack，不拒绝冲突；当前账本没有请求摘要。 | **复现确认**：第二次 target=2 未执行，但返回第一次 target=1 的成功。`services/body.py:170–179`、`storage/actions.py:49–52`。绑定规范化请求摘要，内容冲突显式拒绝；持久化已接收/执行中/结果未知及物理核验信息。不要把去重称为物理原子执行。 |
| A04 | P2 | 进程内顺序任务清理失败后，只清 `_busy`，下一任务继续使用同一 Tool。 | **旧缺陷重新复现**：`runtime/worker.py:90–104`。将清理失败标记为 poisoned，重建 Worker 或终止该批次，保持串行/进程后端一致的隔离语义。 |
| A05 | P2 | 观测接入服务 close 对 handler 无界 gather；空闲客户端不关闭即可拖住退出。 | **旧缺陷重新复现**：`infra/ingest_server.py:66–73`。跟踪连接并关闭，设置有界 drain/取消/回收预算；明确底层线程写入完成的边界。 |
| A06 | P2 | 默认 run_id 精度为秒，同名输出目录无排他预约，重复运行覆盖产物。 | **旧缺陷重新复现**：`runtime/experiment.py:140`、`task_adapters/evaluator.py:236`。使用随机唯一后缀并原子预约；显式同名默认拒绝，resume 单独定义。 |
| A07 | P2，数据可信度 | DatasetBuilder 只筛 succeeded；`split_seed` 被记录但不参与划分，排序后按 index%10 分桶。新增 episode 可改变旧样本分组，相关任务/场景可能跨训练和测试集。 | **静态确认**：`extensions/datasets.py:18–38`。分别保存成功示范与失败/纠正数据；按场景/对象/任务族分组并冻结 split manifest，seed 真正参与确定性分配。泄漏是风险，本次未证明某个实际数据集已泄漏。 |

A01 的线程隔离补丁也不等同于硬实时安全：取消 Python 协程不能终止厂商线程或已经发生的运动。验收必须同时覆盖控制器停止、运动停止证据以及新动作拒绝。

**四、设计已提出、实现尚未闭合的能力**

1. **机器人端执行权与强动作契约。** `schemas.py:86–117` 的 Action/Chunk 以可扩展 dict 为主；`services/body.py:487` 仅检查 chunk/action session 一致和正超时。尚未形成必需的 authority epoch、机器人启动会话、operation ID、计划版本、发布摘要、关节顺序/单位/坐标系、状态前置条件的完整接收契约。`deadline_ns` 当前明确使用 Unix 时间，不能当作设计中的机器人单调时钟窗口。应新增受控的本体 profile 和接收网关，在旧执行权、旧观测、重启、时钟异常、NaN/Inf、维度错误时拒绝动作。允许扩展 metadata 不等于这些规则已执行。

2. **物理对账与取消完成。** 账本只返回持久化成功 ack，动作实际完成到 ack 写入之间仍有故障窗口；Coordinator 自动恢复未实现。设计中的 RECONCILING、结果 UNKNOWN、停止确认和执行权交接尚未闭合。先做机器人本地对账，再谈自动重试或调度器高可用。真机模板默认不自动重试是合理选择。

3. **新鲜世界状态。** 已有 ObservationFrame 的时间、age、calibration 字段，但对这些字段的全库检索未发现相应的统一动作准入策略；`stale_observation_policy` 当前主要停留在 schema。STM 的 `physical_belief` 是模型更新的 dict，尚非带证据、有效期、目标身份和不确定度的状态估计。补齐观测来源/同步窗口/标定版本，并将“观察到、推断、预测、未知”分开。

4. **多速率运行时。** XR365 默认参考图仍为 plan → action → body → observe → verify → evaluate，队列有余量时继续消费。它便于回归和调试，但未提供下一块推理与当前动作执行重叠、已执行前缀约束和切换连续性的完整协议。`RealRobotBody.control_rate_hz` 当前只校验并存储，未建立控制周期。优先测 p50/p95/p99 的观测年龄、推理时延、块间停顿、截止期违约，再按证据优化。

5. **部署配置应表达真实能力。** 真机 Body 配置的 `kind=ros2` 是标签，驱动仍需注入；同一模板 `heartbeat_ttl_s=3600` 不适合作为失联保护的已验收阈值。应区分仿真加速、调试与真机运行 profile，启动时校验必需驱动、停机能力和实际 watchdog 配置。停止时间预算从本体与场景验收导出，不在通用框架里猜一个安全数字。

6. **发布与学习闭环。** release registry 有状态和内容 hash，但哈希不等于签名、兼容性证明或验收门禁。模型、控制器、动作适配、归一化、相机/标定和运行配置需要绑定版本；失败/人工接管/恢复片段进入有许可与标签的数据集，再做离线训练、固定测试集、影子评测和受控发布。Memory/Skill 扩展当前属于基础构件，尚无完整持续学习的效果证据。

**六、建议实施顺序与验收条件**

| 顺序 | 工作包 | 可审查的完成条件 |
|---|---|---|
| 1：当前开发周期 | 修 A01–A06；A07 纳入数据构建改造 | 把复现用例改为期望正确行为的正式测试；同步 SDK 不阻塞控制事件循环，字符串 false 拒绝，同键异内容拒绝，清理失败淘汰资源，退出有界，同名运行拒绝 |

| 3：真机接入前 | 单本体 profile、命令网关、执行权与观测有效期、停止确认与对账 | 用假驱动/硬件在环覆盖旧 epoch、旧 session、时钟异常、延迟观测、丢 ack、半完成动作、失联与人工接管；UNKNOWN 不自动重复副作用 |
