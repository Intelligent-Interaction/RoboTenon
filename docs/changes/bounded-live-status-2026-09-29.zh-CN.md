# 限制实时状态快照大小

[English](bounded-live-status-2026-09-29.md) · [**简体中文**](bounded-live-status-2026-09-29.zh-CN.md)

`robotenon/runtime/runner.py` 现在为每个 episode 保留最近最多 256 个时间线 span 和 256 个事件。正常运行状态的快照每秒最多写一次，启动、终止和错误状态立即写入。span ID 按单调序列生成，不随保留窗口长度变化。`timeline_window` 显示窗口上限、span 总数及是否已丢弃较早记录。

该修改只限制实时监控快照，Graph 执行、观测、模型历史、动作块、环境步数及最终统计沿用原有行为。单独启用的完整 Trace 继续采用既有机制。实时文件只包含最近的时间窗口。

在运行中的服务器上，只读测量了一份 episode 快照的序列化开销。

| 快照 | Span 数 | JSON 字节 | 3 次 JSON 序列化耗时中位数 |
| --- | ---: | ---: | ---: |
| 原快照 | 9335 | 5765523 | 0.154733 s |
| 最近窗口 | 256 | 251041 | 0.006140 s |

该快照的序列化时间约降至原来的 1/25，按秒限制写入频率带来的收益另计。没有测量模拟器端到端加速。测量期间没有修改或重启正在运行的仿真进程。

回归测试运行包含 300 个节点的成功和失败 Graph，验证所有节点均执行、最终输出正确、保留的 span 数量受限且 ID 唯一、正常写入限频，以及终止和错误状态立即落盘。

已启动的 Python Worker 继续使用之前导入的实现。仅替换磁盘文件不会改变其性能。通过受控重启应用补丁，保留已有评测产物并显式处理未完成的 episode。统一 CLI 没有自动续跑参数。
