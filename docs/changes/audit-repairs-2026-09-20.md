# Independent audit repairs (2026-09-20)

[**English**](audit-repairs-2026-09-20.md) · [简体中文](audit-repairs-2026-09-20.zh-CN.md)

This change addressed R01–R11 from the [independent audit](audit-2026-09-20-independent/独立审计.md). It preserved uncommitted infrastructure plugins, environment parameters, documentation, and other existing work. The original audit and defect-presence probes were retained. The 40 regression cases in `tests/test_audit_repairs.py` verify the repaired behavior.

| Issue | Repaired behavior | Verification |
| --- | --- | --- |
| R01 Incomplete stop | Persist Coordinator, Worker, and model process identities. The Portal can reap them independently and reports `released=true` only after exit. `stopping` and `stop_failed` block new dispatch. Children inherit run/resource locks. | Real process backend, blocking synchronous Worker, and a fake model ignoring SIGTERM. Tested forced termination by the Portal and early forced Coordinator exit. Locks remained held while descendants survived and released on exit. Stale PIDs were left alone. |
| R02 Cancellation missed stop | External cancellation, watchdog, and shutdown use a bounded low-level stop. External cancellation propagates `CancelledError`. New actions are rejected while a synchronous driver remains active. Shutdown timeout raises an error. | Blocked driver in a dedicated thread, stop callback, cancellation propagation, reuse refusal, and close timeout. |
| R03 Invalid booleans contaminated STM | `subtask_success` must be a JSON boolean and belief updates must be objects. Validation runs before any STM write. | true/false, strings, numbers, null, arrays, objects, missing fields, and malformed belief. Invalid inputs left memory intact. |
| R04 Scheduling key collision | Identify cases by adapter + index and validate adapter/index uniqueness before execution. Refuse completion when finished count differs from total. | Two seeds of the same task/episode ran concurrently. Finishing the fast case still left the scheduler waiting for the slow one. Duplicate indices were rejected before dispatch. |
| R05 Synchronous SDK blocked the event loop | Ordinary hardware driver calls run in one dedicated executor thread. Stop uses an independent thread. Connect, health, and shutdown have budgets and actions retain deadlines. | Event timers ran while a fake synchronous SDK blocked. A 25 ms action timeout triggered hold. Verified threads and lifecycle. |
| R06 Exposed control endpoints | Bind all Compose published ports to host loopback. Reject remote Portal startup without a token by default and authenticate reads/writes when configured. Limit anonymous Grafana to Viewer and remove the default admin password. | Host/Origin and authentication regressions, real HTTP read/control endpoints, and Compose configuration validation. |
| R07 Mixed configuration versions | Persist the complete merged configuration as a hashed snapshot for Workers and subprocesses. Every task assembles components from it, as do queueing, historical graphs, forks, and reruns. | Edited source midrun. Existing Worker retained old values and new Worker received new ones. In-process and process backends agreed. Fork forms and explicit overrides retained correct provenance. |
| R08 Idempotency conflicts acknowledged as success | Store a digest of action type, payload, and resource scope in the success ledger. Conflicting requests or unverifiable legacy records return a conflict without sending an action. | In-memory and SQLite persistence, matching retries after restart, payload conflict rejection, and legacy ledger rejection. |
| R09 Ingestion shutdown stalled | Stop accepting connections, close clients, and bound the wait for handlers/in-flight writes. Preserve timeout errors when a thread is still writing. | Shutdown with idle and partial-message clients. A blocked write reported a timeout and shutdown completed after the write resumed. |
| R10 Failed resources reused | Clean up resident Tools after task failure and rebuild after successful cleanup. Cleanup failure or timeout permanently invalidates that Worker instance. | After `end_session` failed the next task restarted the Tool. Repeated calls after `close` failure could not revive the old Worker. |
| R11 Run overwritten | Add UUIDs to generated run IDs. A persistent reservation and exclusive file lock reject duplicate new runs. Explicit resume verifies the original configuration hash. | IDs remained unique with a frozen clock. Repeated IDs preserved original files. In-place reruns succeeded, changed-config resume was rejected, and precreated Portal directories were accepted correctly. |

Verification used macOS arm64, Python 3.11.10, and Pydantic 2.13.5. The [verification evidence](audit-2026-09-20-repairs/verification.json) records full Python/frontend results, commands, and changed-file hashes. New fault cases used isolated temporary directories, fake drivers, and a lightweight local model service, without connecting to GPU models or robots.

Linux `/proc` identity parsing had regression coverage, but this machine did not run the existing Linux native-render crash test. Docker Compose configuration parsed successfully without starting or upgrading containers. Hardware SDK thread safety, actual stop confirmation, and Linux/GPU deployment still require acceptance on target systems.

For deployment and compatibility, see [execution contracts and access boundaries](../execution-and-observability.md#64-full-portal-access-boundaries).

- Local and SSH-tunnel deployments retain login-free access. Shared networks require `ROBOTENON_PORTAL_TOKEN` and HTTPS/SSH transport. Reserve `--loopback-published` for loopback publishing.
- The first automatic Grafana startup can generate a random admin password. Direct Compose startup requires `.env`. Updating environment variables does not rotate passwords in existing Grafana volumes.
- Legacy idempotency ledgers lacking a request hash reject automatic retries. Verify actual execution before assigning a fresh key to a new action.
- Historical experiments without a snapshot can migrate and rerun in place only while the original configuration hash can be verified. Otherwise preserve history and create a new experiment.
- The snapshot does not include plugin source, model weights, or environment assets. Pin those versions separately, and keep custom model commands within the managed process group.
