# 独立审计修复记录（2026-09-20）

[English](audit-repairs-2026-09-20.md) · [**简体中文**](audit-repairs-2026-09-20.zh-CN.md)

本次落实 [独立审计](audit-2026-09-20-independent/独立审计.zh-CN.md) 的 R01–R11。修改基于审计后的当前工作区，保留已有基础设施插件、环境参数、文档等未提交工作；原审计及“缺陷存在即通过”的探针不改写。修复后的预期行为由 `tests/test_audit_repairs.py` 中 40 项回归用例验证。

| 问题 | 修复后的行为 | 验证重点 |
| --- | --- | --- |
| R01 停止不完整 | 持久记录 Coordinator、Worker、模型进程身份；Portal 可独立清理；只有相关进程退出才返回 `released=true`。`stopping`、`stop_failed` 阻止队列继续派发。运行锁和资源锁由子进程继承。 | 实际进程后端、同步阻塞 Worker、忽略 SIGTERM 的假模型；Portal 强杀和提前强杀 Coordinator 两条路径；残留期间锁仍占用，退出后释放；过期 PID 不被误杀。 |
| R02 取消遗漏停止 | 外部取消、看门狗和关闭共用有界底层停止；外部取消继续抛出 `CancelledError`。同步驱动仍在执行时拒绝新动作；关闭超时明确报错。 | 驱动在独立线程持续阻塞；检查停止调用、取消传播、拒绝复用及关闭超时。 |
| R03 错误布尔值污染 STM | `subtask_success` 必须是实际 JSON boolean；belief 更新必须是对象；不合格输出在写 STM 前拒绝。 | true/false、字符串、数字、null、数组、对象、缺字段及 belief 格式错误；错误输入不改动记忆。 |
| R04 调度键冲突 | 使用 adapter + index 标识 case，执行前校验适配器和索引唯一性；完成数不等于总数时拒绝报告完成。 | 相同任务/episode 的两个种子并发，快任务结束后仍等待慢任务；重复 index 拒绝派发。 |
| R05 同步 SDK 阻塞 | 真实机器人驱动普通调用运行在专用单线程执行器；停止使用独立线程。连接、健康、关闭有时间预算，动作仍受 deadline 约束。 | 假同步 SDK 阻塞时，事件循环定时器可运行；25 ms 动作超时触发 hold；验证调用线程和生命周期。 |
| R06 暴露控制面 | Compose 所有发布端口绑定宿主回环地址；远程 Portal 默认拒绝无令牌启动，配置令牌后读写都认证；Grafana 匿名权限降为 Viewer，管理员密码无默认值。 | Host/Origin 和认证回归；真实 HTTP 读/控制接口；Compose 配置校验。 |
| R07 配置混用 | 完整合并配置保存为带哈希的快照，传入 Worker 和子进程；每个任务从同一快照构建组件。排队、历史图、Fork 和重跑也使用快照。 | 执行中改源文件，旧 Worker 保持原值、新 Worker 使用新值；进程内与进程后端一致；Fork 表单及显式覆盖保持正确来源。 |
| R08 幂等异内容误确认 | 成功账本增加请求哈希，包含动作类型、payload、资源作用域；同键异内容或旧记录无法核验时返回冲突，不发送新动作。 | 内存与 SQLite 持久化、重启后相同请求重试、异内容拒绝、旧账本拒绝。 |
| R09 观测接入关闭挂起 | 停止接入并关闭客户端连接，有界等待处理器和在途写入；超时保留错误，不把线程仍在写入误报为已完成。 | 空闲/半包客户端无需配合即可关闭；阻塞写入超时报错，恢复后可完成关闭。 |
| R10 失败资源复用 | 任务失败先清理驻留工具，成功后再重建；清理失败或超时会永久停用该 Worker 实例。 | `end_session` 失败后下个任务重新启动工具；`close` 失败后连续调用也不能重新启用旧 Worker。 |
| R11 运行覆盖 | 默认运行 ID 增加 UUID；持久占用记录及独占文件锁拒绝重复新运行；保留显式 resume，校验原配置哈希。 | 冻结时钟下两次默认 ID 仍唯一；重复 ID 不改原文件；原地重跑正常；变更配置的 resume 被拒绝；Portal 预建目录不误判为重复运行。 |

验证使用 macOS arm64、Python 3.11.10、Pydantic 2.13.5。完整 Python 和前端测试结果、执行命令及变更文件哈希保存在 [修复验证资料](audit-2026-09-20-repairs/verification.json)。新增关键故障场景使用隔离临时目录、假驱动及本地轻量模型服务，没有连接真实 GPU 模型或机器人。

验证边界：Linux `/proc` 身份解析已有回归用例，但本机没有执行原有的 Linux 原生渲染崩溃测试。Docker Compose 已验证配置解析，没有启动或升级现有容器。真机 SDK 的线程安全、实际停止确认以及 Linux/GPU 部署仍需在目标环境验收，不能以本机测试代替硬件验证。

部署与兼容变化见 [运行契约与访问边界](../execution-and-observability.zh-CN.md#64-完整-portal-的访问边界)：

- 本机和 SSH 隧道使用方式保持免登录；共享网络需要 `ROBOTENON_PORTAL_TOKEN` 与 HTTPS/SSH 传输保护。不要把 `--loopback-published` 用于公网端口发布。
- 首次自动启动 Grafana 可创建随机管理员密码；直接 Compose 启动需要 `.env`。已有 Grafana 数据卷中的密码不会因环境变量改变而自动轮换。
- 旧幂等账本没有请求哈希时拒绝自动重试。先核对实际执行状态；确认是新动作后再使用新键。
- 历史实验若没有配置快照，只能在原配置哈希仍可核验时迁移并原地重跑；否则应保留历史记录并创建新实验。
- 配置快照不包含插件源码、模型权重和环境资产；部署仍需固定这些版本。自定义模型命令应留在托管进程组内。
